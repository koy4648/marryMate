# 장기 운영으로 전환하기

## 현재 구성

- 화면: Sites (`marry-mate-together.koy4648.chatgpt.site`)
- API: 이 Mac의 Docker에서 실행하는 Spring Boot
- DB: 같은 Mac의 Docker MySQL과 영구 볼륨
- 외부 API 연결: Cloudflare Quick Tunnel
- 코드와 DB 스키마 변경 이력: GitHub, Flyway 마이그레이션

현재 링크로 테스트를 진행하면서 같은 서비스의 운영 환경을 옮길 수 있다. 화면 주소는 기존 Sites에 보유 도메인을 연결해서 정리할 수 있다. API와 DB를 상시 실행 환경으로 옮기면 Mac의 전원과 잠자기에 의존하지 않게 된다.

## 운영 구성

1. 화면은 현재 Sites를 유지하고 서비스 도메인을 연결한다.
2. Spring Boot API를 상시 실행되는 서버에 배포한다.
3. 데이터를 보존하는 별도 MySQL에 연결한다. 자동 백업과 복원 경로를 준비한다.
4. 화면이 새 API 주소를 사용하도록 빌드하고, API가 새 화면 도메인을 허용하도록 설정한다.

DB를 다른 곳에 연결한 뒤에도 API가 Mac에서 실행되면 로그인과 저장은 계속 Mac의 상태에 의존한다. 상시 운영 전환은 API와 DB를 함께 다룬다.

## 데이터와 연결 이전 순서

1. 운영 도메인, API 호스팅, MySQL 접속 정보를 확정한다.
2. 원본 MySQL 전체를 백업하고 새 MySQL에 복원한다. 사용자·공간·업체·후기·패키지·결제와 `flyway_schema_history`를 포함하며 ID와 관계를 보존한다.
3. 새 API에 DB 호스트·포트·DB명·계정·비밀번호를 설정한다. 외부 DB 연결은 해당 환경의 TLS 설정을 사용한다. 현재 로컬 개발용 DB 연결 옵션은 운영 환경에 맞춘다.
4. 새 API를 기동하고 Flyway 검증, 로그인, 공간 권한, 저장·재조회, 패키지 예산·추가금, 결제 일정·방문 시간의 유지 여부를 확인한다.
5. 최종 전환 직전에 쓰기를 잠시 중단하고 최신 데이터를 한 번 더 백업·복원해 전환 중 누락을 막는다.
6. 프론트의 `VITE_API_BASE_URL`을 새 HTTPS API 주소로 변경해 다시 빌드·배포한다. API의 `MARRY_MATE_CORS_ORIGINS`에는 사용할 화면 도메인을 반영한다.
7. 도메인 연결을 전환하고 새 주소에서 확인한다. 원본 백업과 기존 환경은 복원용으로 보관한다.

DB 접속 비밀번호 등 서버용 비밀 값은 API 호스팅의 환경변수로 관리한다. `VITE_` 값은 브라우저에 공개되므로 API 주소처럼 공개 가능한 값만 넣는다.

## DB 외에 보관되는 설정

- 계정·준비 기록·계약·추가금·납입 내역은 DB에 있다. DB를 복원하면 같은 계정으로 이어서 사용할 수 있다.
- 로그인 상태, 마지막 공간, 카테고리 순서·정렬 설정은 현재 브라우저에 있다.
- 화면 도메인을 바꾸면 다시 로그인하고 화면 설정을 다시 선택할 수 있다. 기기 간 동일한 화면 설정이 필요하면 해당 설정도 서버 저장 방식으로 확장한다.

현재 배포 주소와 Mac 기반 실행 환경을 유지한 상태에서 위 전환을 준비할 수 있다. 도메인과 호스팅을 정하면 해당 환경에 맞춰 실제 이전을 진행한다.
